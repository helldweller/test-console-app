# TestConsole

Консольная утилита для Windows. Она находит самую свежую установленную версию приложения `TestApp.exe` в каталоге `C:\Prog\`, записывает в её `config.xml` два числовых параметра и запускает `TestApp.exe`.

## Зачем это нужно

Допустим, на машине лежит несколько версий `TestApp` в разных папках, например `C:\Prog\v1\`, `C:\Prog\v2\` или `C:\Prog\build-2026-11-04\`. Перед каждым запуском TestApp нужно:

1. выбрать актуальную версию;
2. прописать в её `config.xml` параметры запуска `<Arg1>` и `<Arg2>`;
3. запустить её.

Делать это вручную долго, и легко ошибиться: открыть не ту папку, забыть поправить конфиг, запустить две копии сразу. `TestConsole.exe` выполняет все три шага одной командой:

```cmd
TestConsole.exe 5 10
```

Утилиту удобно вызывать из ярлыка, bat-файла, планировщика заданий или CI-скрипта.

## Как это работает

Алгоритм выполняется строго по шагам.

### 1. Проверка единственного экземпляра

При старте `TestConsole.exe` создаёт системный mutex `Global\TestConsole`. Префикс `Global\` значит, что mutex один на всю машину: на все сеансы и всех пользователей, включая RDP-сессии.

Если mutex уже занят другим экземпляром `TestConsole.exe`, утилита выводит ошибку и завершается с кодом `1`. Остальные шаги не выполняются.

> Защита действует, только пока работает сам `TestConsole.exe`, то есть доли секунды. Запускать несколько копий `TestApp.exe` она не мешает, потому что TestConsole не ждёт завершения TestApp (см. шаг 5).

### 2. Поиск актуальной версии TestApp

TestConsole рекурсивно обходит **все вложенные каталоги** `C:\Prog\` на любую глубину. Файлы в самом `C:\Prog\` не учитываются.

Кандидатом считается каталог, в котором есть **оба** файла:

- `config.xml`
- `TestApp.exe`

Из кандидатов выбирается каталог с самой поздней датой изменения `config.xml` (`LastWriteTime`). Дата `TestApp.exe` и имя папки на выбор не влияют.

Если `C:\Prog\` не существует, к нему нет доступа или ни один каталог не подошёл, TestConsole выводит ошибку и завершается с кодом `2`.

Пример:

```
C:\Prog\
├── v1\
│   ├── config.xml      изменён 01.11.2026
│   └── TestApp.exe
├── v2\
│   ├── config.xml      изменён 03.11.2026   ← будет выбран
│   └── TestApp.exe
└── v3\
    └── config.xml      изменён 04.11.2026   (нет TestApp.exe — пропускается)
```

### 3. Проверка аргументов

Утилита ожидает **ровно два** аргумента, и оба должны быть целыми числами типа `int` (от `-2147483648` до `2147483647`).

| Аргументы       | Результат                                       |
|-----------------|-------------------------------------------------|
| `5 10`          | корректно                                       |
| `-3 +7`         | корректно (знак допускается)                    |
| *(без аргументов)* | предупреждение, шаг 4 пропускается           |
| `5`             | предупреждение (нужно ровно два)                |
| `5 10 15`       | предупреждение (нужно ровно два)                |
| `abc 10`        | предупреждение (не число)                       |
| `5.0 10`        | предупреждение (не целое)                       |
| `0x10 10`       | предупреждение (шестнадцатеричная запись не поддерживается) |
| `99999999999 1` | предупреждение (выходит за пределы `int`)       |

Числа разбираются независимо от региональных настроек Windows (`CultureInfo.InvariantCulture`).

Если аргументы не прошли проверку, TestConsole выводит предупреждение, **не меняет** `config.xml` и сразу переходит к шагу 5: TestApp всё равно запускается со старым конфигом.

### 4. Запись аргументов в config.xml

Первый аргумент записывается во **все** элементы `<Arg1>`, второй — во **все** элементы `<Arg2>`. Элементы ищутся на любом уровне вложенности документа. Пространство имён XML не учитывается: `<Arg1>` найдётся, даже если у документа задан `xmlns`.

До:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Settings>
  <Name>Test</Name>
  <Params>
    <Arg1>0</Arg1>
    <Arg2>0</Arg2>
  </Params>
</Settings>
```

После `TestConsole.exe 5 10`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<Settings>
  <Name>Test</Name>
  <Params>
    <Arg1>5</Arg1>
    <Arg2>10</Arg2>
  </Params>
</Settings>
```

Как устроена замена:

- **Всё или ничего.** Если в файле нет хотя бы одного из тэгов `<Arg1>` или `<Arg2>`, файл не меняется совсем и выводится предупреждение.
- **Безопасная запись.** Новое содержимое сначала пишется в `config.xml.tmp` в той же папке, затем подменяет оригинал через `File.Replace`. Если запись прервётся, исходный `config.xml` останется целым.
- **Форматирование сохраняется.** Отступы, переносы строк и остальные элементы остаются как были.
- **Любой сбой — только предупреждение.** Битый XML, файл только для чтения или занятый другим процессом: TestConsole выводит предупреждение и продолжает работу, TestApp всё равно запускается.

После успешной записи дата изменения `config.xml` обновляется. Этот каталог и так был самым свежим, поэтому при следующем запуске выбор версии не изменится.

### 5. Запуск TestApp.exe

`TestApp.exe` запускается из найденного каталога. Рабочим каталогом процесса назначается тот же каталог, поэтому TestApp найдёт свой `config.xml` по относительному пути.

TestConsole **не ждёт** завершения TestApp: он запускает процесс и сразу выходит с кодом `0`. Если TestApp — консольное приложение, оно откроется в своём окне.

Если запустить `TestApp.exe` не удалось (файл повреждён, нет прав, заблокирован антивирусом), TestConsole выводит ошибку и завершается с кодом `3`.

## Требования

### Для запуска

- Windows 10 / 11 или Windows Server 2016+.
- .NET Framework 4.8. В Windows 10 (начиная с версии 1903) и Windows 11 он уже установлен. Для более старых систем его можно скачать с сайта Microsoft.
- Права на чтение `C:\Prog\` и подкаталогов, права на запись в `config.xml` выбранной версии.

### Для сборки

Подойдёт любой из вариантов:

- **.NET SDK 5.0 или новее** на Windows, Linux или macOS. Проверено на .NET SDK 8.0. SDK сам скачивает из NuGet справочные сборки .NET Framework 4.8 (пакет `Microsoft.NETFramework.ReferenceAssemblies`), поэтому при первой сборке нужен интернет.
- **Visual Studio 2019 (16.8+) или 2022** с рабочей нагрузкой «Разработка классических приложений .NET» (.NET desktop development).

## Сборка

### Через .NET CLI (Windows, Linux, macOS)

```bash
git clone https://github.com/helldweller/test-console-app.git
cd test-console-app
dotnet build -c Release
```

Результат появится в `bin/Release/net48/`:

| Файл                     | Назначение                                                    |
|--------------------------|---------------------------------------------------------------|
| `TestConsole.exe`        | сама утилита (~9 КБ)                                          |
| `TestConsole.exe.config` | указывает нужную версию .NET Framework (`v4.8`)               |
| `TestConsole.pdb`        | отладочные символы, для работы не нужен                       |

Отладочная сборка: `dotnet build` (результат в `bin/Debug/net48/`).

> Собранный на Linux или macOS `TestConsole.exe` запускается только на Windows.

### Через Visual Studio

1. Откройте `TestConsole.csproj` (*Файл → Открыть → Проект/решение*).
2. Выберите конфигурацию **Release**.
3. *Сборка → Собрать решение* (`Ctrl+Shift+B`).

Результат будет в той же папке `bin\Release\net48\`.

## Установка

1. Скопируйте `TestConsole.exe` и `TestConsole.exe.config` в любую папку, например в `C:\Prog\` или `C:\Tools\`. Корень поиска от этого не зависит, он всегда `C:\Prog\`.
2. Убедитесь, что версии TestApp разложены по подкаталогам `C:\Prog\`, и в каждом есть `TestApp.exe` и `config.xml`.

Устанавливать что-то ещё или прописывать в реестр не нужно.

## Использование

```
TestConsole.exe <Arg1> <Arg2>
```

| Параметр | Тип   | Куда записывается      |
|----------|-------|------------------------|
| `Arg1`   | `int` | тэг `<Arg1>` в `config.xml` |
| `Arg2`   | `int` | тэг `<Arg2>` в `config.xml` |

### Примеры

Записать параметры и запустить актуальную версию:

```cmd
C:\Prog\TestConsole.exe 5 10
```

Запустить актуальную версию, не трогая `config.xml` (будет предупреждение):

```cmd
C:\Prog\TestConsole.exe
```

Отрицательные значения:

```cmd
C:\Prog\TestConsole.exe -1 -100
```

### Пример вывода

Успешный запуск:

```
Найдена версия: C:\Prog\v2
config.xml обновлён: Arg1=5, Arg2=10.
TestApp.exe запущен.
```

Неверные аргументы:

```
Найдена версия: C:\Prog\v2
Предупреждение: Ожидаются 2 целочисленных аргумента: TestConsole.exe <Arg1> <Arg2>. config.xml не изменён.
TestApp.exe запущен.
```

Версия не найдена:

```
Ошибка: В подкаталогах C:\Prog\ не найдены config.xml и TestApp.exe.
```

### Ярлык на рабочем столе

1. ПКМ на рабочем столе → *Создать → Ярлык*.
2. Объект: `C:\Prog\TestConsole.exe 5 10`.

Окно консоли закроется сразу после запуска TestApp. Чтобы прочитать сообщения, запускайте утилиту из `cmd` или PowerShell.

## Сообщения и коды возврата

Ошибки выводятся в **stderr** и останавливают работу. Предупреждения и информационные сообщения выводятся в **stdout** и работу не останавливают.

| Код | Когда                                         | Сообщение                                                                 |
|-----|-----------------------------------------------|---------------------------------------------------------------------------|
| `0` | TestApp запущен (даже если были предупреждения) | `TestApp.exe запущен.`                                                  |
| `1` | уже работает другой экземпляр TestConsole     | `Ошибка: TestConsole.exe уже запущен.` / `…уже запущен (другим пользователем).` |
| `2` | ошибка поиска или версия не найдена           | `Ошибка: Ошибка поиска в C:\Prog\: …` / `Ошибка: В подкаталогах C:\Prog\ не найдены config.xml и TestApp.exe.` |
| `3` | не удалось запустить TestApp.exe              | `Ошибка: Не удалось запустить TestApp.exe: …`                             |

Предупреждения (код возврата остаётся `0`):

| Ситуация                              | Сообщение                                                                 |
|---------------------------------------|---------------------------------------------------------------------------|
| аргументы не прошли проверку          | `Предупреждение: Ожидаются 2 целочисленных аргумента: …`                  |
| в config.xml нет `<Arg1>` или `<Arg2>` | `Предупреждение: В <путь> нет тэга <Arg1> или <Arg2>. Файл не изменён.`   |
| не удалось прочитать или записать config.xml | `Предупреждение: Не удалось обновить <путь>: <причина>`             |

### Проверка кода возврата в скриптах

bat / cmd:

```bat
@echo off
C:\Prog\TestConsole.exe 5 10
if %ERRORLEVEL% neq 0 (
    echo TestConsole завершился с ошибкой %ERRORLEVEL%
    exit /b %ERRORLEVEL%
)
```

PowerShell:

```powershell
& 'C:\Prog\TestConsole.exe' 5 10
if ($LASTEXITCODE -ne 0) {
    Write-Error "TestConsole завершился с ошибкой $LASTEXITCODE"
    exit $LASTEXITCODE
}
```

## Ручная проверка

Автотестов в проекте нет: корень `C:\Prog\` зашит в код, а .NET Framework 4.8 работает только на Windows. Ниже сценарии для проверки на Windows вручную.

**Подготовка** (PowerShell). Создаёт две тестовые версии; в роли `TestApp.exe` выступает копия Блокнота:

```powershell
foreach ($v in 'v1', 'v2') {
    New-Item -ItemType Directory -Force "C:\Prog\$v" | Out-Null
    Copy-Item "$env:WINDIR\System32\notepad.exe" "C:\Prog\$v\TestApp.exe"
    Set-Content "C:\Prog\$v\config.xml" '<Root><Arg1>0</Arg1><Arg2>0</Arg2></Root>'
    Start-Sleep -Seconds 1   # чтобы у v2 config.xml был новее
}
```

**Сценарии:**

| # | Действие | Ожидаемый результат |
|---|----------|---------------------|
| 1 | `TestConsole.exe 5 10` | выбран `C:\Prog\v2`; в `v2\config.xml` Arg1=5, Arg2=10; открылся Блокнот; код `0` |
| 2 | `TestConsole.exe abc` | предупреждение; `config.xml` не изменён; Блокнот открылся; код `0` |
| 3 | убрать `<Arg2>` из `v2\config.xml`, затем `TestConsole.exe 1 2` | предупреждение про отсутствующий тэг; файл не изменён; код `0` |
| 4 | сделать `v1\config.xml` новее (изменить и сохранить), затем `TestConsole.exe 7 8` | выбран `C:\Prog\v1` |
| 5 | удалить `TestApp.exe` из обеих папок, затем `TestConsole.exe 1 2` | ошибка «не найдены»; код `2` |
| 6 | переименовать `C:\Prog`, затем `TestConsole.exe 1 2` | ошибка поиска; код `2` |

Код возврата смотрится через `echo %ERRORLEVEL%` в cmd или `$LASTEXITCODE` в PowerShell.

**Очистка:** `Remove-Item -Recurse C:\Prog\v1, C:\Prog\v2`.

## Ограничения и особенности

- **Корень зашит в код.** Путь `C:\Prog\` задан константой `Root` в `Program.cs`. Чтобы сменить его, поменяйте константу и пересоберите проект.
- **Недоступный подкаталог прерывает поиск.** В .NET Framework 4.8 рекурсивный обход падает на первом каталоге без прав на чтение. В этом случае TestConsole выдаёт ошибку с кодом `2`, даже если подходящие версии есть в других папках.
- **Одинаковые даты.** Если у нескольких `config.xml` совпадает время изменения, выбирается любой из них.
- **Остаточный файл `config.xml.tmp`.** Если временный файл записался, а подмена оригинала не удалась (например, `config.xml` только для чтения), `config.xml.tmp` останется в папке. На работу TestApp он не влияет, его можно удалить.
- **XML-декларация и кодировка.** После записи файл начинается с XML-декларации (`<?xml version="1.0" encoding="…"?>`), даже если её не было. Кодировка берётся из декларации; если её там нет, файл сохраняется в UTF-8 с BOM.
- **TestApp не получает аргументов командной строки.** Параметры передаются только через `config.xml`.
- **Запуск TestApp от имени администратора не запрашивается.** Если TestApp требует повышенных прав, Windows покажет запрос UAC сама, по манифесту TestApp.
